# gxShell 项目 review：2026-11-04

本次审阅覆盖桌面后端、CLI/MCP 入口、SSH/SFTP、隧道、设置与备份、凭据、
远程管理模块，以及前端的终端、文件、文档和 AI 流程。主要检查授权边界、
并发与取消、关闭后的资源清理、文件写入和凭据暴露；结合现有测试与新增回归
测试验证。大型模块按关键调用路径抽查，未逐行审计全部代码，也未连接生产服务器。

## 已确认并修复的问题

| 优先级 | 问题与触发条件 | 影响 | 修复及证据 |
| --- | --- | --- | --- |
| P2 | 移除／停止隧道只关闭监听，已接受的连接继续转发。 | UI 显示隧道已关闭后，原连接仍可能访问目标，直至自身或 SSH 会话关闭。 | 每个 forward 登记两端连接；停止时取消拨号、关闭监听及全部连接。`TestRemoveTunnelClosesAcceptedConnections`、`TestForwardStopClosesBothSidesAndCancelsDial`。 |
| P2 | 动态 SOCKS5 隧道忽略客户端 METHODS，一律选择无认证。 | 只声明支持其他认证方式的客户端收到违反协议的成功选择；后续通信不可靠。 | 仅在客户端提供无认证方式时选择它，否则返回 `0xff`；同时校验保留字段、域名和端口。`TestNegotiateSOCKSRejectsUnavailableAuthMethod`、`TestNegotiateSOCKSRejectsInvalidRequestFields`。 |
| P2 | 启动后等待八秒的更新任务不重新检查开关。 | 用户在等待期间关闭自动更新检查，程序仍请求更新源；原等待也不响应退出。 | 请求前重新读取开关；等待和请求绑定应用 context。`TestDisabledBackgroundUpdateNeverContactsFeed`。 |

对应实现：`backend/tunnel/tunnel.go` 和 `internal/app/app_update.go`。

## 代理功能的检查

- 设置提供 system/direct/manual，默认 system；SSH 代理独立 opt-in，默认关闭。
- AI 与更新请求共用动态 transport，已有流不会因保存设置被主动切断。新增测试
  `TestAIUsesSavedProxyAndAppliesChangesWithoutRestart` 验证真实 HTTP 模型请求在
  保存后切换到第二个本地模拟代理。
- 第一跳 SSH 支持 CONNECT 和 SOCKS5，保留 CONNECT 响应后提前到达的 SSH
  banner；限制响应头大小，连接与握手受 context 取消控制。
- localhost 和回环地址直连，避免本地 AI、CLI/MCP 被代理。
- 无效手动配置不能替换已保存设置；URL 内凭据被拒绝；无效磁盘配置阻止外部
  请求。备份导入保留本机代理设置。
- 测试覆盖路由、排除列表、HTTP 代理、CONNECT banner／取消／超大响应头、
  SOCKS5 域名转发、SSH opt-in 与第一跳取消、设置持久化。

用户说明：[应用代理](../proxy.zh-CN.md)。

## 授权与其他审阅路径

- CLI/MCP：令牌认证、Host/Origin 检查、profile opt-in、原生审批、请求去重、
  后台任务及取消；两种 MCP 传输复用现有 CLI 授权路径。
- SSH：第一跳与跳板、握手超时、断开、命令启动与取消、会话复用。
- 文件：SFTP 临时写入、元数据恢复、传输与恢复；本地文档授权、链接、文件类型、
  保存冲突和大小限制。
- 设置与数据：配置标准化、备份预览／回滚、凭据迁移与脱敏、日志和录制路径。
- 前端：终端生命周期、会话恢复、文件传输回调、Markdown/Mermaid 清理与 AI 输出。
- 远程操作：Docker、服务、防火墙、计划任务与网站命令的输入校验和引用。

除上表外，这些路径未发现可直接确认的新业务缺陷。命令风险分类仍是协作式
自动化的审批策略，不能把任意脚本当作沙箱；详见 `docs/agent-guide.md`。
