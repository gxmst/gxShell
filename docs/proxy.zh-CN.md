# 应用代理

在 **设置 → 应用代理** 中选择连接方式，然后保存。代理设置只控制 gxShell
自身的出站请求，不修改 Windows 全局代理。

| 设置 | 行为 |
| --- | --- |
| 跟随系统（默认） | Windows 使用当前用户的静态代理、PAC 或 WPAD；`HTTP_PROXY` / `HTTPS_PROXY` 环境变量优先，并遵守 `NO_PROXY`。其他平台使用这些环境变量。 |
| 直连 | 不使用代理，也不读取系统或环境变量中的代理地址。 |
| 手动代理 | 所有适用请求使用指定的 HTTP、HTTPS 或 SOCKS5 代理，排除列表中的目标直连。 |

手动地址必须带协议和端口，例如 `http://127.0.0.1:7890`、
`https://proxy.example.com:8443` 或 `socks5://127.0.0.1:1080`。
`socks5h://` 也可使用，SOCKS5 的目标域名在代理端解析。
当前手动模式支持无认证代理；带用户名或密码的 URL 会被拒绝。

排除列表支持域名、IP 和 CIDR，使用逗号或分号分隔。例如：

```text
*.example.com,10.0.0.0/8,192.168.1.10,<local>
```

`<local>` 排除不含点的主机名。`localhost`、其子域名以及回环地址始终直连，
因此本地 AI 服务、CLI 控制接口和 MCP 服务不会绕到代理上。

## 哪些功能使用代理

- AI 对话、模型列表和更新检查使用所选策略。更新检查仍受原来的独立开关控制。
- **SSH 连接使用代理** 默认关闭。开启后，新 SSH 连接和跳板机的第一跳使用
  所选策略；HTTP/HTTPS 代理使用 CONNECT，SOCKS5 使用 TCP 转发。
- 保存后新的请求立即使用新设置。进行中的 AI 流和已建立的 SSH 会话继续运行；
  要让已有 SSH 会话切换路线，需要重新连接。
- 跳板机到目标服务器的连接、服务器上执行的命令及其网络访问仍发生在服务器端。
  外部浏览器、ICMP/UDP 网络诊断和反向隧道的本地目标连接不使用此设置。

手动代理不可达时，请求返回连接错误，不自动改用直连。无效配置不会保存；
如果磁盘上的代理配置无效，启动后会阻止外部请求，直到在设置中修正。
备份恢复保留目标电脑自己的代理设置。

Windows PAC/WPAD 解析有阶段超时，不会自动发送 Windows 登录凭据。
代理是否允许 CONNECT 到 SSH 端口取决于代理服务器；很多 HTTP 代理只允许 443。
本次验证使用了本地模拟代理；真实企业 PAC/WPAD 和认证代理尚未实机验收。
